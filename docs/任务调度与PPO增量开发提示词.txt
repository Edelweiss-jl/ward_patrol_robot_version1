3. 任务创建、数据和兼容

3.1 页面和保存语义

- 复用现有点选模式、床位输入和跨层选择。允许手输「楼层 / 床位编号」，显示按楼层分组的已选床位，支持单项移除。不同楼层均叫 B03 的床位可同时加入。同一床位从画布和手输入口重复加入时，提示具体项，例如「2 楼 / B03 重复选择」。同编号有歧义时引导补楼层或直接点选。保持现有点选再次点击移除的交互。
- 新保存流程由服务端生成唯一任务编号和创建时间。页面保存前可显示「保存后生成编号」，保存后展示编号、创建时间和待分配状态。客户端使用独立的幂等请求标识重试，同一标识和同一有效内容返回同一任务，内容冲突需明确反馈。创建时间可用带时区的真实时间显示，优先级和截止时间可编辑。队列排序以核心明确的创建顺序和稳定编号破同分。
- 本设计对新手动任务的目标语义是「保存成功即待分配」，无需再点发布。沿用已有任务区和队列组件，将「保存并发布」和手动批量发布限制在仍需要处理的历史未发布记录或明确保留的兼容入口。旧保存记录按原语义读取，旧的未发布条目不得自动投入执行，旧的已发布条目不得重复建单。旧 API 和 CLI 有既有调用时保留相同行为。任何在无运行或暂停状态下的保存行为都不得偷偷启动或推进仿真。
- 保存检查字段形状、计时值和身份引用的基本格式。床位业务检查只做按「楼层 ID＋床位 ID」去重。车辆能力、电量、路线、电梯、电量安全下限和调度可行性留到入队后处理。地图版本或床位对象无法解析时显示定位和处理方式。沿用保存地图后才可绑定正式版本的流程，已绑定版本随任务记录，不随当前编辑或浏览版本变化。新版本上的运行若与记录不匹配，明确提示并留存原绑定。

3.2 主任务、床位项、片段与尝试

  主任务 → 唯一任务编号、创建时间及稳定排序键、地图 ID 与版本、来源、模板 ID 与期次、优先级、释放时刻、可选截止时刻、整单状态、结束原因、最近一次调度尝试。床位数和完成数可从床位项派生。
  床位巡检项 → 所属任务、楼层 ID、床位 ID 和本次任务所用的服务点 ID，保存名称快照，记录服务方式、当前尝试、执行状态、到站、开始服务、完成时间和结果。
  分配片段 → 关联主任务和安排版本，记录车辆、所含床位、访问顺序、分楼层路线、电梯段与预约、预计时刻及预计最低电量。一个片段由一台车执行，车辆可顺序执行多个片段。
  执行尝试 → 记录尝试编号、床位项、车辆、计划版本、开始和结束时间、原因及采样/确认标识。改派只对仍需执行的床位创建新尝试。

主任务与全部床位项须一次持久化，初始均为待分配。分配片段在方案成功提交后才产生。优先复用已有持久化锁和原子写入手段。无运行时保留待分配记录；运行准备、恢复和服务重启时，通过现有命令队列按任务编号幂等接收。核心确认前显示正确的等待状态。历史任务、床位 ID、旧快照和回放缺少新增字段时仍可读。正在执行和终态任务的恢复以已落盘的命令与事件为依据，验证恢复过程不会重复派单或完成。

3.3 周期模板

- 模板保存床位清单、地图版本、优先级、服务方式及参数、首次发布时间、间隔、次数和每期完成时限。首次可设立即，正式执行时间均使用仿真时钟。页面显示下一期时刻、已生成次数，并可打开每期任务。
- 到期创建各自独立的任务编号、床位项、创建和释放时间、模板 ID 与期次。截止时刻等于该期释放时刻加允许完成时长。上一期未完成时，下一期仍按时进入待分配。固定步恢复时处理所有应到的期次，保留原释放时间和独立期限。
- 用「模板 ID＋期次」保证扫描、重启与重试幂等，生成任务与更新模板发布记录需一致。修改参数只影响尚未生成的期次。既有一次性批量或周期入口保留兼容。
- 验收例为仿真第 0 秒首次发布，间隔 120 秒，三次，每次允许 90 秒完成。应得到三张任务，释放时刻为 0/120/240 秒，截止为 90/210/330 秒。重复扫描和重启后仍各只有一份。

4. 电梯、整单方案与派车

4.1 仿真边界和候选生成

- 本多层验收场景采用所有车辆都能通过门、都能乘电梯的设定。沿用车型几何和连通性校验，用样例尺寸实现该条件。A* 继续检查楼层内实际几何、限制规则和已知阻塞。历史窄门样例仍可验证不可达。调度只读取已知地图、已发布管理事件、车队状态、资源状态和机器人上报的堵塞证据。局部控制遵守阶段 3 的有限观测边界。训练和评估可用真值结算指标，推理不得把未来事件作为输入。
- 调度定时按仿真步扫描，车辆空闲、故障解除和电梯资源释放可触发重扫。按优先级降序、截止时间升序、创建顺序升序及稳定 ID 处理，无截止任务在相同优先级下排在有截止任务之后。前面的任务暂时无法安排时记录原因，并继续检查后续任务。重复触发要合并，调度频率不随倍速改变仿真口径。
- 先按楼层组合床位。同层优先尝试一台当前在该楼层的车连续访问；覆盖不足、续航不足或赶不上截止时，再按真实路径成本拆给多台车。补充跨层调车方案，允许一台车在目标楼层连续访问多个床位。候选车辆须空闲、健康、能力匹配、没有冲突预约，并满足人工锁定规则。
- 每套候选要恰好覆盖全部未完成床位一次，给出车辆、床位顺序、行程路线、资源时段和预计完工时刻。楼层内复用 A*，跨层复用阶段 4 的关键点图和行走、候梯、进梯、乘梯、出梯动作。预约、放行、实际占用分开，按电梯、床位和充电设施各自的容量规则校验。对容量为 1 的电梯核对整段无重叠。出口堵塞时保留实际占用，确认离开才释放。
- 预计耗时包括行驶、等梯、进出梯、乘梯、等待、床旁服务和已有的必要补能。人工确认、MQTT 回执的完工预测用可配置等待预算，实际由有效服务完成事件结算。多车并行时，整单预计完工取最晚结束的片段。沿用已有电量消耗和安全阈值规则。充电和返航只有在能耗、充电点占用和返航校验都实现后才计入正式可行性，缺失能力记录为待验收。
- 先过滤违反覆盖、截止、电量、路线、能力和资源约束的候选，再保留有实质差异的可行安排。候选可分别偏向乘梯最少、完工最早、保留紧缺楼层空闲车、使完工后车辆分布更适合后续任务。同一辆车与相同顺序、路径和资源安排的重复方案应去重。候选数量与 tie-break 固定可复现。建议默认 8 个有效候选槽位，可配置。
- 候选暂缺时记录受影响楼层、床位和最近失败依据，例如车辆忙、电梯忙、通道暂时堵塞、本轮路径规划失败。只有能证明覆盖所有合法选择的乐观完工下界仍超过截止时刻，才提前判分配失败。普通不可达或搜索预算内无解保持待分配。已到截止而未完成的任务按状态机结算。

4.2 选择、复核与提交

规则基线在可行候选中优先乘梯次数最少，其次预计完工最早，再按距离、等待及稳定 ID 破同分。PPO 与规则使用同一个候选生成器和复核提交入口。确定方案后，在同一固定步检查任务及计划版本、地图版本、车辆状态、电量、床位覆盖、当前路线和全部资源时段是否仍有效。车辆安排、床位片段和资源预约一次提交。复核失败时释放临时占用，记录原因并重新评估。页面从提交后的状态显示「已分配」。

验收至少覆盖同层零乘梯可行、同层资源不足而需要跨层、单车连续访问目标楼层多个床位、多车并行、前序任务阻塞后继续扫描、方案复核失效后无残留预留。保留原有紧急插单、人工锁定和故障恢复阶段要求。可用小规模穷举辅助核对覆盖和选车结果。

5. 执行、详情、故障和归档

- 主任务状态应清楚区分待分配、已分配、执行中、暂停、召回中和终态。第一台车真正开始后进入执行中。床位项记录待访问、前往中、到站服务中和已完成；必要时显示阻塞或接管。到站和开始服务分别记录，只有停留计时完毕、有效人工确认、有效 MQTT 回执才完成服务。
- 队列显示任务编号、优先级、截止、整单状态和完成床位数。详情按车展示楼层、位置、床位顺序、路线、预计完成以及逐床进度。人工确认入口仅在允许的服务状态显示。显示具体等待原因、影响楼层和床位。可呈现「A 车负责 1 楼两床，B 车负责 2 楼一床，预计乘梯 1 次，预计提前 18 秒完成」这样的可核对摘要。
- 区分全局仿真暂停和单任务暂停。全局暂停冻结仿真时钟；单任务暂停经命令队列让相关车辆安全停靠，仿真和该任务截止时钟继续。恢复时重新检查位置、电量、路线、剩余时间及资源。取消、召回显示安全停靠或回撤进度，车辆到达安全状态才可接下一单，按退出时的实际资源状态释放。重复取消、召回、确认、回执和释放须幂等。
- 电梯延迟或路线受阻时，先修复受影响路线或预约，尽量保留可继续的片段。故障车辆应记录异常并隔离，尝试接管其未完成床位；局部调整不可行时，对受影响的剩余床位生成新候选。允许规则或已启用的 PPO 用同一接口重选。每次改派生成新尝试编号。人工确认和 MQTT 回执校验当前尝试。迟到或重复回执留痕，完成过的床位结果保留。
- 到达截止时刻，先处理该时刻及之前在仿真步内生效的有效完成事件，再一次性结算整单。全部完成为成功，仍有未完成项为超时；保存已完成的局部结果。终态还应区分分配失败、主动取消、召回完成、最终执行异常。故障后成功接管且按时完成，按成功归档。归档须能按任务 ID、日期、状态、车辆查询。
- 同一权威记录供列表、详情、统计、回放和 CSV 使用。归档包含原床位清单、地图版本、每版计划及候选指标、选中原因、规则或模型版本、实际轨迹、操作和生效步、逐床服务事件、改派及结束原因。能关联主任务 ID、床位项、片段、尝试、运行和车辆 ID。重点验收结束边界、暂停与截止、取消与回执同一步竞争、故障接管和旧回执无效。

6. 集中式带动作掩码的 PPO

- 一个车队共用一个策略。业务规则选下一张有可行候选的任务；PPO 一个动作选择一套完整候选方案。可行性、任务状态、资源占用、故障处置和安全动作继续由现有业务模块负责。没有候选时记录原因并推进仿真；有可行候选时立即进入选择流程。提交前复用规则策略的复核。规则方案为默认，可显式配置启用新模型。模型不可用或推理结果失效时按规则重新选择/复核，并记录实际采用的策略及原因。旧 adaptive、Q-learning、单车与双车 PPO 继续用于原用途。
- 观测包括任务优先级、等待时间、截止余量、按楼层聚合的待巡检床位和预计服务耗时；车队各层空闲数、忙车预计可用时间、电量与占用；其他已知任务的楼层需求和近期截止；电梯位置、运行与预约、各层预估等待。允许纳入已配置周期模板的将来释放摘要；未知的未来任务只通过训练场景的生成规律体现。
- 每候选统一提供预计完工、截止余量、乘梯数、等梯、距离、预计最低电量、占用楼层和完工后车辆分布。固定形状可采用每楼层统计与 8 个候选槽位。训练采样与运行推理使用同一掩码定义，屏蔽空位、失效方案和无法提交的方案。记录候选顺序、掩码和选择，处理全掩码时由环境自动推进。候选动作索引只在该次决策有效。 动作掩码参考论文（https://arxiv.org/abs/2006.14171）
- 训练环境以固定仿真调度间隔推进事件，按队列顺序为下一张可派任务做一次选择；没有可派任务时按仿真步自动推进。训练、评估和正式运行使用同一仿真时间口径与核心规则。记录环境版本、配置、特征格式、掩码定义、种子、模型和训练产物的新路径。先跑小规模无窗口冒烟和确定性对照，再开展已授权训练。

奖励建议与结算口径

每个调度步按该区间内的新增事件结算：按时成功主任务的优先级加权奖励 − 最终失败主任务的优先级加权惩罚 − 实际乘梯惩罚 − 实际等梯时间惩罚 − 已释放任务新增待分配时间惩罚。

  按时成功 → 普通任务 +10，全部床位完成服务后整单只结算一次。
  最终失败 → 普通任务 −15，超时、确定分配失败和最终执行异常按整单结算一次。主动取消、召回单列，训练中用明确的外部事件规则处理。
  优先级 → 高优先级可先对成功和失败两项乘 1.5。
  乘梯 → 每次实际开始一段乘梯 −1。直达多个楼层算一段；下梯再乘梯另计。一次预约本身不计实际乘梯。
  等梯 → 各车实际新增等梯每 10 仿真秒 −0.1。
  任务待分配 → 已释放仍待分配的各任务新增等待每 10 仿真秒 −0.05。

权重可配置。复核已结算任务不会重奖重扣，失败接管成功后按最终状态结算。测试至少包含当前任务多乘一次电梯但为随后的紧急任务留车的场景，以及后续影响相近、少乘梯更合适的场景。结论以未参与训练的对照数据为准。

7. 公平评估、日志和验收

使用同一候选生成器、A*、电梯模型、发布输入、任务状态机和指标口径，对比以下三组：规则选择乘梯最少、PPO 无电梯成本、PPO 有电梯成本。无电梯成本组只将乘梯和等梯惩罚设为零，保持观测、候选、任务和其他奖励项相同。训练覆盖连续任务、不同截止时间、楼层负载不均、电梯拥堵、低电量及故障。以未训练过的种子和任务序列验收。外部故障、阻塞和请求需能按实际生效步复跑。观察窗口内已释放任务尽量结算，未结算任务单列并报告分母的处理方式。

  主任务按时完成率 → 按时成功主任务数 ÷ 已释放主任务数，另报高优先级组。
  超时、分配失败、执行异常、取消、召回 → 分别报告数量和占已释放任务的比例。未完成到观察结束的也单列。
  平均等待 → 已开始主任务的首次执行时刻减释放时刻，另报从未开始占比。训练奖励的逐步待分配时间另记。
  机器人利用率 → 巡检执行时长 ÷ 在线可运营时长，同时列出充电、等梯、其他资源等待、故障的时间，保持互斥分类和相同窗口。
  电梯使用 → 分别报告预计与实际乘梯、等梯时间；同时报告每个已释放任务和每个成功任务的实际乘梯量。先比较完成和超时，再解释资源成本。

按阶段做最小必要的回归。至少包含不同楼层同名床可保存、同一床重复提示、保存重试与重启、周期期次幂等、整单提交失败无残留、容量与故障、截止边界、人工与 MQTT 尝试匹配、任务暂停与全局暂停、事件与结果可核对、候选掩码在训练和推理一致。展示回放验证保存的快照与事件；实验复跑验证同地图、种子、配置和命令实际生效步。只报告实际跑过的模式、试验次数和阻塞项。
