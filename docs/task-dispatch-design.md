# 病房巡检任务管理与多机器人调度设计

一张巡检任务可以包含不同楼层的多个床位，有独立的优先级、创建时间和截止时间。用户始终跟踪同一个任务编号。调度器可以把床位分成多个片段，交给一台或多台机器人执行。每个片段由一台车负责，同一个任务的片段可以并行，无需同步开始。截止时间前全部床位的服务都完成，整单才成功。

设计参考 Calvo 与 Capitán 的异构多机器人任务分配框架，采用可分片任务、能力与电量约束、在线启发式分配，以及局部修复和重规划。论文中的连续接力和同步联盟适用于有连续性或同步要求的任务。这里以独立床位访问为执行单元。优先级排序、整单硬截止、跨楼层资源和归档规则由病房巡检业务定义。[参考论文](https://arxiv.org/abs/2411.02062)

## 1. 任务、床位与机器人记录

| 对象 | 主要字段与用途 |
| --- | --- |
| 主任务 | 内部唯一 ID、显示编号、地图 ID 和版本、创建时间、释放时间、优先级、截止时间、状态、最近原因、首次分配与执行时间、结束时间。显示编号可由用户输入或由系统生成，服务端校验唯一性。 |
| 床位巡检项 | 主任务 ID、楼层 ID、床位或服务点 ID、显示名称快照、服务参数、状态、到站与完成时间、完成依据、执行尝试编号。同一床位在不同周期可以分别巡检。 |
| 分配片段 | 主任务 ID、分配版本、负责车辆、床位顺序、路径、预计开始和完成时间、预计耗电、占用的资源、实际执行状态。重新分配时保留旧版本。 |
| 机器人运行状态 | 车辆和车型 ID、当前位置与楼层、能力、当前电量与安全下限、占用状态、当前片段、可用时间预估。运行时以实时位置和楼层为准。 |
| 任务事件 | 事件 ID、任务和执行尝试 ID、仿真时刻、操作者或机器人、操作、状态变化、原因。保存分配尝试、控制命令、到站与服务结果、资源和故障事件。 |

表单支持画布点选和手输「楼层 / 床位编号」，切换楼层保留选项。保存时，服务端按指定地图版本解析输入并逐项校验楼层存在、床位存在且确实归属该层、有可用服务点、床位未重复，同时检查编号、服务参数、优先级和截止时间。失败时一次返回有问题的床位及原因，不生成半张任务。成功后原子写入主任务与床位项，使任务立即进入「待分配」，无须再手动发布；当前没有匹配地图版本的仿真时，原因显示为「等待对应仿真启动」。

任务模板和周期发布继续使用。每个周期生成独立任务实例，保存各自的释放时间、截止时间、床位进度和结果，并关联模板与周期序号。周期截止时间按释放时刻加模板规定的时间窗计算。记录创建时间用于查看和审计，调度时间使用统一仿真时钟。任务尚未绑定运行时可保存相对截止窗口，绑定后换算为该运行的仿真截止时刻。仿真加速或全局暂停影响仿真时钟推进，单任务暂停期间仿真时钟仍推进。任务默认绑定保存时的地图版本，地图改名或后续编辑不改变历史床位与路径。

## 2. 状态流转与详情页

| 状态 | 进入条件及详情页内容 |
| --- | --- |
| 待分配 | 保存校验通过。展示床位、剩余时间、最近调度时间，以及等待仿真、车队繁忙、暂时阻塞、规划失败等原因。实际规划失败时保留该状态，等资源或环境变化后重试。 |
| 分配失败 | 已有足够依据判断在当前任务约束下无法按时安排全部床位，例如可证明的最乐观完工时间也超过截止时间。保存判定依据和候选明细，纳入终态归档。 |
| 已分配 | 全部床位均已有通过复核的路径、车辆和资源安排。展示每台车、负责床位、路径与预计开始时间。 |
| 正在执行 | 第一台车确认开始片段。逐车展示当前位置、剩余路线和预计完成时间，逐床展示待访问、前往、到站服务、已完成等进度。 |
| 已暂停 | 暂停命令生效，显示暂停时间、停靠位置和剩余床位。恢复前从当前位置复核路线、资源、电量与截止时间，必要时重新分配。 |
| 召回中 | 停止启动新的巡检点，车辆从安全位置前往停车点或指定安全点。显示召回路径和各车回撤进度。 |
| 执行异常 | 机器人故障或执行失去可靠控制时立即显示，记录故障车、受影响片段和已完成床位。可接管时记录异常事件并返回正在执行或已分配；修复与重规划均失败时，以执行异常归档。 |
| 执行成功 / 超时 / 用户取消 / 已召回 | 分别对应全部床位在截止时刻或之前完成、截止时仍有未完成的床位、用户明确取消、所有被召回车辆到达安全点。保留最终床位明细、分配记录、实际轨迹和事件。 |

停留计时以规定服务时长结束为准，人工确认以到站后的有效确认事件为准，MQTT 采样以本次服务尝试收到符合条件的响应为准。车辆到站更新进度，只有服务完成事件才计入整单完成。截止时刻同一仿真步内，先处理时刻不晚于截止的有效完成事件，再判超时。归档锁定任务结果，随后到达的旧事件可记入日志。取消或超时后车辆仍可能在安全停靠或回撤，车辆状态单独展示，等车辆安全释放后才能接下一单。

暂停默认保留已完成的床位，并在安全位置停住，释放未开始且可安全释放的预约。召回和取消在停止继续巡检后作废原分配的执行尝试，召回以回到安全点为操作目标，取消记录用户主动终止。恢复、召回或取消都作用于整张任务涉及的车辆。对于故障车，只接管未完成床位；人工确认和 MQTT 响应用任务、床位及执行尝试编号校验，避免旧车辆的确认写入新分配。

## 3. 调度器如何选任务和选车

1. **读取同一时刻的快照。** 每个调度周期处理车辆状态、执行事件和用户命令，再从已到释放时间且地图版本匹配的待分配任务开始扫描。车辆空闲、故障、资源释放等事件可触发提前扫描。任务按「优先级降序 → 截止时间升序 → 创建时间升序 → 任务 ID」排列。同一轮里，前一张任务资源不足时继续评估后一张任务。
2. **生成候选分片。** 单层先尝试整体安排给一台车。如果合跑会超过安全续航、后续无法按时完成，或拆分能提高截止时间余量，则按地图可达关系和床位之间的 A* 距离试拆。多层先按楼层形成候选分片，层内可再拆。分片必须覆盖全部尚未完成的床位，每个床位只在一个有效分片中。
3. **筛选兼容车辆并预估。** 首版只给当前空闲、未被预约、健康且能力匹配的车辆分配。用车型尺寸、床位服务能力、实时位置、楼层可达性、电量等条件过滤。时间估算包括行驶、床边服务、必要的充电与资源等待。人工确认用可配置的预计等待时间，MQTT 用采样预计时长和响应超时预算；实际结果以执行时的事件为准。对正忙车辆可以计算最早可用时间来区分「暂时繁忙」和「确认不可行」。
4. **组合车辆和分片。** 用临时车队与资源占用表试排，先安排候选最少的片段，再安排预计耗时更长的片段。候选车先按对整单预计完工时刻的影响排序，再比较换层次数、总距离和等待时间，最后用稳定的车辆编号打破平局。若贪心选择导致后续片段无车，可以在计算预算内尝试下一候选或替代拆法。同一台车在一张计划中可以顺序完成多个片段，执行时同一时刻只运行一个片段。
5. **生成正式路径并一次提交。** 调用与预览和运行共用的 A* 规划器逐段生成路径，按真实路径复核耗时、床位互斥、电量以及资源预约，再校验任务、车辆、地图、计划版本是否仍与快照一致。全单可行才一次写入车队队列、资源预约和「已分配」状态。任一点规划失败则释放本轮临时占用，任务继续待分配并记录原因。机器人空闲时从已提交的队列依序确认和启动片段，启动前再次核验资源及计划有效性。

整单预计完成时间取所有片段预计完成时刻的最大值。一个片段包含多段路线和服务时，各段时间累加，资源等待和充电时间也计入。硬约束要求整单预计完成时刻不晚于截止、每一段剩余电量都达到各车安全下限、所有床位恰好分配一次，以及任一独占资源在同一时段只被一个有效计划使用。若启用预充电，必须计入去充电站的时间和耗电、排队和充电时间，并检查到达充电站前的电量下限。若需保留安全返回能力，估算时也预留最后一个床位至安全点的电量。

**分配失败与等待应有可复核的判定。** 当兼容车辆的最早可用时间加上乐观的最短移动与最短服务时间，仍不能覆盖至少一个必检床位，可以给出提前失败的证据。用于提前失败的时间下界须包含所有仍可能的合法车辆和路径，并省略无法保证一定发生的等待。静态能力或固定策略下永久不可达也可记录为分配失败。一次启发式没有找到整单方案、分配时所有空闲车的当前预估超期、或存在暂时性堵塞时，继续显示待分配和具体风险原因。到截止时仍未完成则记为超时，并记录当时是否从未分配、从未开始或已部分完成。

## 4. 跨楼层策略待定

任务表单、校验、床位进度和整单截止都支持跨楼层床位。跨楼层执行方式保留为配置策略，等实际选择确定后再接入执行器。

| 可评估策略 | 调度规则 |
| --- | --- |
| 按楼层派车 | 每个片段只能由可以在目标楼层运行的车辆覆盖。不同层的车辆可并行，主任务仍须一次提交全部楼层的分配。 |
| 允许车辆乘电梯 | 给具备换层能力的车辆增加楼层间连接。只有路线实际涉及换层的车辆才要求该能力。路径由单层 A* 段和电梯段拼接，预估含走向入口、等待、乘梯、出梯和后续行驶。电梯调度记录开放楼层、占用时段和容量，一个预约只支持相应时段内的执行。 |

楼层或电梯未覆盖时，详情页明确显示受影响的床位和原因。若运行尚未选定跨楼层策略，跨楼层任务可保存并显示「等待配置跨楼层执行策略」。电梯在地图上的入口负责定位连接点，乘梯调度和运行状态由独立资源模块提供。

## 5. 执行监控、局部修复和重规划

中央调度器维护任务、车队、资源和计划版本，车辆执行器按顺序运行「移动 → 到站 → 服务」，按需执行充电和获准的楼层切换。状态、路线、到站及服务事件通过现有仿真快照和 SSE 更新页面。执行器报告中间进度，主任务服务负责聚合状态和完成结果。

| 事件 | 局部处理与升级条件 |
| --- | --- |
| 行驶变慢、通道临时阻塞 | 先刷新当前路线或后续预计时间，利用计划中的时间余量，校验电量、截止时间和资源预约。约束失效后重算受影响的剩余计划。 |
| 电量低于预估、资源延迟 | 先检查可安全等待、改道或补能的选项。换车能够保住截止时，只迁移受影响的床位；仍解不开冲突时扩大重规划范围。 |
| 车辆故障 | 立即进入执行异常并隔离故障车。撤销它的未完预约，保留已完成床位，回收其未完成床位并尝试交给兼容车辆。需要先确认车辆已停或操作权已撤销，避免两台车重复服务。 |
| 新任务到达 | 先用可用车辆为新任务找完整方案。若需要重新安排，优先调整尚未开始的片段，复核原任务的截止和资源承诺。 |

局部修复成功时提交新版本并继续执行。失败时，以实时位置、电量和剩余床位为新输入，重规划受影响的未完成工作，必要时扩展至所有未开始的安排。保留已完成的服务结果，正常执行中的服务尽量维持原安排。任务已经被取消、超时或归档时，迟到的分配计算和服务回执不能使任务重新进入执行状态。

## 6. 与现有系统的对接

| 位置 | 设计变更 |
| --- | --- |
| `ward_patrol_web/workspace.py` | 从「保存后手动发布」迁移为保存即入持久化队列，增加地图版本与床位归属校验、显示编号和主任务查询。旧记录按原含义导入：历史已发布记录保留其运行关联，未发布记录先校验并补齐所需字段再入新队列。 |
| `ward_patrol/runtime/editable.py` | 当前按床位独立派同层车，可复用车型通行、电量估算、床位互斥以及停留、人工确认和 MQTT 执行器。增加整单调度和片段队列，已派单床执行器只运行分配指定的巡检项。 |
| `ward_patrol_web/server.py` | 沿用 `SimRunner` 的命令队列，在仿真线程提交状态更新。若把路径搜索放到计算线程，只传入快照和规划参数，结果返回后由仿真线程检查版本再提交。 |
| 编辑器与运行页 | 表单加入编号、优先级和截止时间，任务列表提供活动和归档视图。详情中按楼层和车辆展示路线与床位状态，保留暂停、恢复、召回和取消操作。 |

保存与派单命令设置幂等 ID，重复提交返回已有结果。每次分配记录计划版本，取消和重规划使旧计划失效。主任务、分片、床位、预约和事件同步提交，避免出现页面显示已分配而执行队列缺片段。可用 SQLite 事务保存任务与事件，沿用现有运行目录保存地图快照和高频轨迹。仿真结束要结算活动任务，重启时按最后可靠的事件核对命令与结果，缺少可恢复运行快照的中断任务记录为执行异常并保留已完成部分。

## 7. 归档、指标与对比实验

终态任务从活动列表转入归档，仍可按任务编号、地图版本、运行、状态、优先级及车辆检索。归档保留输入快照、预估与实际时间、计划版本、点位服务结果、失败原因和控制事件。日志保留能追溯巡检结果的服务凭据，指标导出只使用床位标识和时序，避免复制患者资料。

| 指标 | 计算口径 |
| --- | --- |
| 任务完成率 | 按时成功的主任务数 ÷ 已释放任务数。实验统计前将观察窗口内的释放任务跑到终态或单列尚未结算项，并同时报告取消及分配失败。 |
| 超时率 | 超时主任务数 ÷ 已释放任务数。提前分配失败单列，以便区分分配阶段和执行阶段的损失。 |
| 机器人利用率 | 各车执行巡检所占的有效时长 ÷ 该车在线可运营时长。另列充电、资源等待和故障时间，车队值由总时长加权计算。 |
| 平均等待时间 | 对已开始任务计算首次开始时间减释放时间的平均值。同时保留释放到首次分配的时间，以及从未开始的比例。 |
| 算法及资源指标 | 记录整批完成用时、行驶距离、充电次数、资源等待时长、每次规划耗时与重规划次数。启用电梯方案时记录乘梯次数和等待时间。 |

实验使用相同的地图快照、车队、任务释放时刻、截止时间与随机种子。基线可用现有「兼容空闲车中选最短路径」规则，沿用同一任务归档和截止判定进行统计。在线算法对比整单分片启发式与修复策略。小规模再用 MILP 对可行解质量作比较，以预生成可达片段、车辆与时刻为输入，约束每个床位恰好覆盖、车辆与资源时序、电量和截止时间。若比较允许拒单的场景，先按优先级最大化可按时覆盖的整单，再优化完工时间、距离和换层等成本，并报告求解时限及最优性差距。论文也使用小规模精确模型比较启发式方案，并在较大场景评估其运行开销。[参考论文](https://arxiv.org/abs/2411.02062)

## 8. 实现顺序与验收示例

1. 先实现保存即入队、状态流转、仿真截止判定、详情与归档，覆盖旧任务兼容和重复提交。
2. 接入同层整单调度与分片，接通现有三种服务。使用 1、2、4 台车验证优先级排序、床位互斥、部分规划失败回滚、暂时无车与确定无法按时完工的区分。
3. 加入暂停、恢复、召回、取消与故障接管，验收截止时刻完成、迟到回执、整单部分完成和运行中断。随后接入局部修复、重规划和指标对比。
4. 等跨楼层执行方式确定后，接入对应策略。按楼层派车应验证多层片段一次提交；电梯方案应验证两车争用、延迟传播和预约释放。

例如，某任务在仿真第 0 秒释放，截止为第 90 秒，1 楼有两个床位，2 楼有一个床位。若实验配置允许按楼层派车，1 楼和 2 楼的兼容车分别预计第 65 秒和第 40 秒完成，整单预计第 65 秒完成。若 2 楼车暂时繁忙，任务仍待分配，详情展示该层预计可用时间；若能证明该层床位最早也要第 100 秒完成，归档为分配失败。若已执行的两台车分别在第 65 秒和第 90 秒完成最后一个床位，整单成功。若第 90 秒仍在等待人工确认，则整单超时，归档仍保留其他两个床位的完成记录。
